# Memory Object Spec (Loop 1–2)

## Stream records (`memory/stream/YYYY-MM-DD.md`)
- Canonical append-only raw event stream for a day.
- Front matter:
  - `type: stream`
  - `date: YYYY-MM-DD`
- Body:
  - One JSON line per ingested event.
  - Must include `event_id`, `created_at`, `text`, `cues`, `state`, and encoding factors.

## Event memories (`memory/events/YYYY/MM/DD/ev-*.md`)
- Durable memories promoted by the encoding gate.
- Front matter:
  - `type: event`
  - `event_id`, `created_at`
  - context fields: `people`, `project`, `place`, `tool`, `mode`, `emotion`, `action`
  - `state`: dictionary-like context snapshot
  - `cues`: sparse cue bundle
  - `source_anchor`: stream anchor (`YYYY-MM-DD.md#event_id=...`)
  - encoding diagnostics: score/threshold/weighted factors
- Body:
  - Original event text (not compressed).

## Daily summaries (`memory/summaries/daily/YYYY-MM-DD.md`)
- Generated by consolidation.
- Front matter:
  - `type: daily_summary`
  - `date`
  - `event_count`
  - `segment_count`
  - `schema_version`
- Body sections:
  - `## Gist` (deterministic high-level statements)
  - `## Anchors` (source links to event memories)
  - `## Segment Notes` (boundary-aware segment descriptors)

## Indexes
- `indexes/inverted_cues.json`: cue → memory paths
- `indexes/state_buckets.json`: state key/value bucket → memory paths
- `indexes/strength_table.json`: memory strength for forgetting/reinforcement loops

## Design intent
- Markdown remains canonical memory substrate.
- JSON indexes are fully derived and rebuildable.
- Every summary statement should map back to one or more event anchors.
